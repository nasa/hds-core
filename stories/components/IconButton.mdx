# Icon Button

Circle-shaped buttons containing a single icon and no visible text. Use them for compact actions where space is limited and the icon's meaning is universally understood. USWDS has no equivalent component — icon buttons use HDS-specific `.hds-btn-icon` classes.

All icon buttons follow the HDS wayfinding convention: **red navigates away**, **blue stays on the page**, **neutral colors are for UI controls**. See [Color](?path=/docs/foundations-color--docs) for more on color roles.

## Variants

### Action roles

Three emphasis levels for actions. Choose based on how much attention the button should draw.

**CTA** (`.hds-btn-icon--cta`) — NASA Red. The action **navigates away** from the current page. Highest emphasis.

**Secondary** (`.hds-btn-icon--secondary`) — NASA Blue filled. The action **stays on the page** — download, share, apply. Primary on-page emphasis.

**Outline** (`.hds-btn-icon--outline`) — NASA Blue border. Same on-page intent as secondary, but **lower emphasis**. Use when secondary feels too heavy alongside other elements.

### Utility

Neutral, adaptive circles for **UI controls** — carousel arrows, accordion toggles, media controls, settings, close. Utility buttons blend into the interface rather than drawing attention. Their color adapts to the surrounding palette automatically.

Use utility icons only with universally recognized icons in predictable locations. The circle outline is a subtle decorative treatment, not a strong interactive affordance — users identify these as buttons through icon meaning and contextual placement.

### Social

Social media sharing and follow links. Use `<a>` tags since these navigate to external platforms.

<Canvas of={IconButtonStories.Social} />

HDS Core ships marks for the platforms NASA maintains an official presence on, the share targets used on nasa.gov and plus.nasa.gov, and GitHub. See [Icons](?path=/docs/foundations-icons--docs) for the full set. All use the `logo-` prefix in the sprite.

HDS ships social marks in a **single grayscale treatment**. There is no brand-colour variant: the neutral circle is used everywhere, on every palette.

```html
<a class="hds-btn-icon hds-btn-icon--social hds-btn-icon--xl" href="https://www.facebook.com/NASA" aria-label="NASA on Facebook">
  <svg class="hds-icon" aria-hidden="true" focusable="false">
    <use xlink:href="/assets/img/hds-sprite.svg#logo-facebook"></use>
  </svg>
</a>
```

This is a deliberate simplification. Brand-coloured social buttons require each platform's official lockup colours, which brings per-platform contrast exceptions, marks whose container cannot be separated from the glyph, and a maintenance burden every time a platform rebrands. A single grayscale treatment sidesteps all of it and keeps a social row visually consistent.

#### Generic share targets

Not every button in a share row is a platform. Four glyphs cover the non-platform cases, and all four already exist in the sprite:

| Glyph          | Use                                                                |
| -------------- | ------------------------------------------------------------------ |
| `share`        | Generic "share this" affordance, for a share sheet or native share |
| `notification` | Subscribe to updates / notification bell                           |
| `rss`          | Feed subscription                                                  |
| `mail`         | Share by email                                                     |

The HDS Figma spec places all of these on the **NASA Blue secondary circle** (`.hds-btn-icon--secondary`), not the social circle — they are on-page actions rather than links to an external platform, which is what the wayfinding rule predicts:

```html
<button class="hds-btn-icon hds-btn-icon--secondary hds-btn-icon--xl" type="button" aria-label="Share this page">
  <svg class="hds-icon" aria-hidden="true" focusable="false">
    <use xlink:href="/assets/img/hds-sprite.svg#share"></use>
  </svg>
</button>
```

`mail` is the HDS envelope from `tag-mail` with its enclosing circle removed and scaled up — not USWDS's envelope, which is a different shape.

#### Bring your own logo

HDS Core cannot ship every platform. If you need a mark we do not have, add it to your own sprite and point `<use>` at it — the button, sizing, focus ring, and hover all still come from HDS:

```html
<a class="hds-btn-icon hds-btn-icon--social hds-btn-icon--xl" href="https://example.social/@nasa" aria-label="NASA on Mastodon">
  <svg class="hds-icon" aria-hidden="true" focusable="false">
    <use xlink:href="/assets/img/my-sprite.svg#logo-mastodon"></use>
  </svg>
</a>
```

Draw your glyph on the HDS convention so it matches the rest of the row: `viewBox="-2 -2 24 24"`, `fill="currentColor"`, no baked-in fill colour, and the mark's bounding box scaled to about 20 units centred at (10, 10).

**Use the platform's own published mark.** Don't redraw a logo by hand and don't recolour one — most brand guidelines forbid both. Check the platform's brand page for a monochrome or single-colour asset, which is what the sprite needs.

#### Marks that carry their own container

Spotify, LinkedIn, and Apple Podcasts publish marks that already contain their own container — a disc or rounded square with the glyph knocked out of it. On the HDS circle that container reads twice, so those three look slightly heavier than the rest of a row.

This is cosmetic, not a compliance problem: each renders that platform's official monochrome logo, which is exactly what their guidelines call for. Separating mark from container would even out the row but every one of them forbids it.

<Note type="figma">
  The HDS Figma social spec dates from 2020 and pairs a grayscale and a brand-colored variant for each platform. HDS Core ships <strong>only the grayscale one</strong> — see Guidance above. Figma also predates several platform rebrands and shows the retired Twitter bird, so marks follow each platform's current official artwork. The Figma grayscale fill is Carbon 80; HDS Core ships Carbon 60, which is deliberate: Carbon 80 measures 1.32:1 against the dark palette background, where the circle would effectively vanish.
</Note>

<Note type="uswds">
  The USWDS footer renders social links as <code>&lt;img&gt;</code>, which CSS cannot recolor. HDS Core ships replacement assets under the same USWDS filenames, so a stock <code>.usa-social-link</code> footer picks up HDS social marks and the HDS circle with no markup change. Note that <code>twitter.svg</code> resolves to the current X mark, since USWDS still ships the retired bird under that name.
</Note>

### Interactive

Disclosure triggers designed for use **over images, video, and 3D content** — not on plain palette backgrounds. Interactive buttons use fixed colors (not palette-aware) for high contrast on dynamic backgrounds.

The visual state inverts on hover and when expanded — NASA Blue Shade + white flips to white + black. Toggle `aria-expanded` to control the active/open state. The consuming application manages the popover show/hide.

<Canvas of={IconButtonStories.Interactive} />

Per HDS Figma accessibility guidance, popovers should **automatically display when the button receives focus** and hide when the user tabs away. When the popover is open, users should be able to tab to the link inside the popover.

```html
<button class="hds-btn-icon hds-btn-icon--interactive" type="button" aria-label="Sample Handling" aria-expanded="false" aria-controls="popover-sample">
  <svg class="hds-icon" aria-hidden="true" focusable="false">
    <use xlink:href="/assets/img/hds-sprite.svg#plus"></use>
  </svg>
</button>

<div id="popover-sample" role="region" hidden>
  <h3>Sample Handling</h3>
  <p>The Sample Handling System is used to collect and store samples.</p>
  <a href="/missions/mars/sample-handling">Learn More</a>
</div>
```

<Note type="figma">
  Interactive icons in HDS Figma use standalone SVGs with baked-in colors. HDS Core uses the standard sprite system with <code>currentColor</code> instead — CSS handles the color inversion on hover and <code>aria-expanded</code>. The visual result is identical.
</Note>

## Sizes

Eight sizes are available. Size and role classes are independent — combine any size with any role.

| Size    | Class                | Container | Use                                   |
| ------- | -------------------- | --------- | ------------------------------------- |
| 2XS     | `.hds-btn-icon--2xs` | 12px      | Filter dropdowns (desktop only)       |
| XS      | `.hds-btn-icon--xs`  | 16px      | Header, footer, compact UI            |
| Small   | `.hds-btn-icon--sm`  | 20px      | Inline with text, cards               |
| Default | _(no modifier)_      | 24px      | General purpose, primary arrow button |
| Large   | `.hds-btn-icon--lg`  | 28px      | Cards, navigation controls            |
| XL      | `.hds-btn-icon--xl`  | 32px      | Social buttons, standalone actions    |
| 2XL     | `.hds-btn-icon--2xl` | 36px      | Hero sections, prominent controls     |
| 3XL     | `.hds-btn-icon--3xl` | 40px      | Pagination arrows, carousel controls  |

<Note type="figma">The HDS Figma icon button spec defines 6 sizes labeled XS through XXL (16–36px). ## When to use

- **Compact actions** where the icon's meaning is universally clear — play, download, share, close, expand
- **Social media rows** — a group of social/sharing icons
- **Carousel and accordion controls** — utility role arrows for previous/next and expand/collapse
- **Action bars** — a horizontal row of secondary actions below content
- **CTA accent** — a small CTA icon paired with adjacent text
- **Disclosure triggers over images** — interactive role for tooltips, popovers, and contextual info

## When to consider something else

- If the action needs a **text label** for clarity, use a [Button](?path=/docs/components-button-guidance--docs) instead
- For **inline text navigation**, use a [Link](?path=/docs/components-link-guidance--docs)
- If the icon's meaning is **not universally obvious** (e.g., a domain-specific glyph), use a text button — don't rely on `aria-label` alone to convey meaning to sighted users
- For **decorative icons** that aren't interactive, use `.hds-glyph` instead. See [Icons](?path=/docs/foundations-icons--docs) for all available glyphs.

## Usability guidance

- **Always provide `aria-label`.** Icon buttons have no visible text — the label is the only way screen readers and voice control users can identify the action.
- **Write action-oriented labels.** "Download report" is better than "Download." "Go to mission page" is better than "Arrow."
- **Use `<button>` for actions, `<a>` for navigation.** If the icon button navigates to a new page, use an `<a>` tag. If it triggers an on-page action, use `<button>`.
- **One icon per button.** Don't combine multiple icons in a single icon button.

<Note type="uswds">The 2xs size (12px) is below the WCAG 2.5.8 minimum touch target size (24×24px). Use only on desktop viewports with a mouse-driven interface. On touch devices, use the default (24px) or larger.</Note>

## Accessibility

- **`aria-label` is required** on every icon button. Without it, the button is announced as empty by screen readers.
- **`aria-hidden="true"` on the SVG.** The icon is decorative — the `aria-label` on the button provides the accessible name.
- **`focusable="false"` on the SVG** prevents a double-focus issue in older browsers.
- **Don't remove focus styles.** HDS Core applies a visible focus ring on all interactive elements.
- **Touch target size.** The default size and above all meet the 24×24px minimum recommended by WCAG 2.5.8. The 2xs and xs sizes are below this threshold — use them only in desktop/mouse contexts.
- **Interactive disclosure buttons** require `aria-expanded` and `aria-controls` linking the button to its popover. The icon glyph must have at least 3:1 contrast against its background. The circle stroke is decorative framing — accessibility does not depend on it being visible.
- **Social marks are grayscale only**, so no per-platform contrast exception is needed. The glyph is Carbon 05 on Carbon 60 — 6.51:1, comfortably above the 3:1 non-text threshold, and identical on every palette. Brand-coloured social buttons would need several WCAG 1.4.11 logotype exceptions; shipping grayscale avoids them entirely.
- **Name the platform in the label, not the glyph.** A brand mark carries no accessible name. Write `aria-label="NASA on Facebook"`, not `aria-label="Facebook icon"`.
- **The social fill is Carbon 60 on every palette, not the Carbon 80 in Figma.** Carbon 80 measures 1.32:1 against the dark palette background, so the circle would effectively disappear there; Carbon 60 holds 2.52:1 on dark and 7.09:1 on white. The circle is decorative framing, so this affects perceived affordance rather than conformance. Flagged for creative director review.

```html
<!-- ✅ Correct -->
<button class="hds-btn-icon hds-btn-icon--secondary" type="button" aria-label="Download report">
  <svg class="hds-icon" aria-hidden="true" focusable="false">
    <use xlink:href="/assets/img/hds-sprite.svg#download"></use>
  </svg>
</button>

<!-- ❌ Missing aria-label -->
<button class="hds-btn-icon hds-btn-icon--secondary" type="button">
  <svg class="hds-icon" aria-hidden="true" focusable="false">
    <use xlink:href="/assets/img/hds-sprite.svg#download"></use>
  </svg>
</button>
```
